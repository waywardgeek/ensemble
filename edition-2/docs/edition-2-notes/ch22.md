### What changed and why

`internal/tools/status.go` formats the existing Engine meter through
`ToolContext.Engine()`, and the shipped primary skill actually permits calling
it. The report includes current model, last response and session input/output/
cache-read/cache-write counts, session cache hit rate, and USD cost when known.
No status service, callback bag, copied counters or second accounting path was
added. The pre-existing Engine map retains vendor/model/tier with counts; its
meter sums costs at the rates for that work. Unknown contributing prices make
the full cost unknown, rather than displaying a misleading partial sum.

The exercise asks for a model switch, but this predecessor lacked an effective
runtime control. `Agent.SetModel` sends one actor message. It rejects empty
models and active turns, updates the Agent's own model, and clears the old
resolved replay identity. It leaves vendor, endpoint, credential provider,
billing, conversation, last usage and per-model counts alone. The terminal
`/model NAME` and GUI Settings model field use it. This is same-provider,
between-turn, session selection; it does not discover models automatically or
promise that an arbitrary identifier is available. The person selects an
account-available model. The GUI broadcasts effective owner state to all tabs;
a model patch is separate from persisted preferences so a busy rejection cannot
partially save an unrelated mixed change. Launch configuration wins on restart.

Production changes are limited to status, this missing switch, declarations,
shipped permission and visible controls/help. Existing architecture was already
coherent; recreating the chapter's broken refactor would make it worse. Tests
and chapter evidence account for most added volume.
