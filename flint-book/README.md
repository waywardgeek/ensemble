# Improving Flint as a Coding Student

An executable codebook under development with Bill and Cadence. Its product is a
reconstructible student configuration and an evidence-based improvement procedure,
not a second implementation of Ensemble or a claim of model-weight training.

## Boundary

The main [coding-agent book](../book/README.md) owns general runtime behavior,
sandboxing, file-tool errors, and trustworthy grading infrastructure. This book
owns the Flint experiment: skills, exposed tools, task packaging, trial inputs,
interventions, comparisons, and the reasons for adopting or rejecting changes.
A trial may discover a general defect. Repair its original teaching in the main
book; record the dependency and effect here rather than duplicate the runtime.
Do not add Flint-specific instructions to every user's primary skill.

## Evidence rules

Record exact route, skill bytes, chapter bytes, tool/runtime version, launch
policy, commands, outcomes and assistance for each trial. A skill name alone does
not identify a configuration. Keep the candidate frozen while grading it.
Distinguish behavioral score, architecture review, instruction compliance,
provider completion and human acceptance. Do not collapse these into one success
number. One improved run is a lead, not causal proof; later tasks must check
whether a change generalizes beyond the task that suggested it.

The current assignment is offline only. The separate live-provider exercise and
Chapter 2 remain unauthorized. No automatic retries, paid fallback, installation,
publication or host restart follows from this document. Existing broader trial
authorization still requires fresh IDs, confinement, and explicit launch policy.

Development earns the chapters. Do not predesign a whole curriculum or present
untested skill instructions as demonstrated improvements.
