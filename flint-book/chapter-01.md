# A smaller student surface

Status: working specification. No full chapter body or acceptance claim yet.

## TL;DR

Construct a compact primary for a confined Flint coding student. It should expose
only file inspection/mutation, commands, command observation, status, clarification
and submission, plus universal controls supplied by the host. Reuse the existing
coding rules rather than invent a weaker architecture. Do not expose delegation,
browser, web search or administrative skills merely because the parent has them.

The skill must teach concrete recovery: supplied workspace versus host checkout;
activated instructions versus source files; create versus replace versus edit;
source clipping versus report clipping; running jobs versus completed commands;
automatic checkpoint resumption; and actual grading versus acknowledgement.

Keep the chapter assignment, sandbox, exact free route and grader unchanged. This
is a new configuration trial, not a rerun or silent repair of the passed baseline.
Architecture and the live exercise remain separate acceptance dimensions.

## Exercises

1. Run the [provider-free skill check](checks/README.md) using Ensemble's actual skill loader. Verify
   the effective tools and active coding instructions, not just YAML syntax. The
   primary must not inherit the parent's unrelated startup skills. Record any
   universally installed controls separately from its explicit grants.
2. Prepare a fresh child home with the public Chapter 1 input and prerequisites,
   a project-local environment recipe, cleared NuGet sources and no target source.
   Record input hashes, absolute project path, exact offering, primary bytes,
   context limit, confinement root and read-only compiler imports before startup.
3. Verify the installed existing-file diagnostic and loaded skill version before
   attributing improvement to them. Use disposable files; failed exclusive creation
   must preserve their contents. Do not inspect or change another Agent's state.
4. Run one authorized offline trial. Retain its original Job handle, collect running
   commands, answer genuine questions, and record every parent intervention. A pause
   is not permission to resume. A provider failure is not a compiler failure.
5. Use the [trusted runner](../scripts/confined-grading/README.md) for parent-mediated
   grading of the frozen candidate. Require exit 0 and `passed:true`, and retain
   its JSON report. Allow at least 360 seconds. Never run the student unrestricted
   or provide a real key. Do not repeat a passing student's run without discussion.
6. Review Common declarations, construction, both relationship ends, destruction,
   request URL and failure handling against the supplied chapter. Report any
   grader coverage gap separately; a behavioral pass cannot waive architecture.
7. Interview once after the result, check suggestions against observed calls, and
   join shutdown. Compare friction and assistance with baseline 01. Record what
   improved, regressed or remains uncertain; do not claim causality from one run.

Completion for this increment means a verified launch configuration, an observed
trial, its graded and reviewed result, and incorporated evidence—not guaranteed
student success. Full Chapter 1 acceptance still needs the separately authorized
live exercise and Bill's judgment. Chapter 2 is not part of this increment.
