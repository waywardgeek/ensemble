### What changed and why

The accepted source already had the star and real parent relationships. Preserved
that architecture. Added `Agent.RegisterTool(ToolDeclaration, handler)` to its
existing ordered, per-Agent registry; public aliases expose the declaration and
`ToolContext`. Registration is synchronous setup before `Ask`, with duplicate
names (including builtins), empty names, malformed JSON and nil handlers rejected.
The registry owns a copy of supplied schema bytes. The existing dispatch/job loop
executes custom handlers; there is no second loop, global registry or callback
service bag. Handler context reaches the actual Engine and owner chain.

Moved the existing environment parser to public `ensemble.ConfigFromEnv`, leaving
CLI builtin/data-directory choices at the CLI. Preserved generic/provider-prefixed
precedence, explicit model configuration, base URL, resolved identity and workspace.
No historical model default was added. The public library remains at
`ensemble/ensemble`; moving files merely to match a sample layout was unnecessary.

Changed the root's concrete `Logger() *log.Logger` exposure to the chapter's narrow
`Logf(format, ...any)` interface. The same Ensemble-owned standard logger supplies
writer synchronization, now with timestamps. Engine and job diagnostics traverse
their existing parents; tools can use
`call.Engine().Agent().Ensemble().Logf(...)`. No invented logger parent, root
shortcut, observer, actor or mailbox was introduced.

`main/ch05/` is a separate Go module and real executable that imports only the
public library. Its application-defined `shout` tool uppercases supplied text,
logs through the owner chain and runs through actual `Ask`. It accepts a human
prompt as ordinary arguments, prints the answer/usage and saves actual events.
Its README gives build/run instructions. It disables builtins so the demonstration
can only use its own tool. No calculator builtin or constant answer was added to
the framework. Example log saving and a bounded context support inspection and
safe, finite demonstrations, rather than adding a framework feature.
