No claim that mutations cover every possible input/error path. Timeouts and

## Student difficulties and author advice

- The chapter's command omits `CH=1`, but Makefile's `grade-dir` passes `-ch $(CH)`.
  Used the explicit variable after reading Makefile; suggest correcting the
  teaching invocation in the later author phase. This was invocation help,
  not answer code from the coordinator.
- Initial live launcher used Python stdin heredoc and handed chat EOF immediately.
  It made no model request. Changed to `python -c` so chat inherited PTY stdin;
  the three-turn run then worked. Teach the difference between feeding a launcher
  and exercising the launched interactive application.
- A first test-file write used a repo-relative path while already in the student
  directory and failed. Command output exposed that no tests had been added;
  corrected the path before claiming test coverage. No application bug involved.
- Original Chapter 1 is sufficient for the conversation loop. Architecture comes
  from Bill's skill/carryover, not the chapter's single-client sample. Explain
  why these owners exist when teaching the revised version, while keeping early
  features this small.
- The exact API version survivor is a useful grader-maintainer finding: checking
  a present header is weaker than checking the documented protocol version.
- Current provider documentation permits consecutive same-role input (combined)
  and assistant-prefill forms. The chapter deliberately imposes a narrower
  alternating user-ended exercise; do not teach that simplification as the
  complete provider contract. This implementation follows the exercise.
