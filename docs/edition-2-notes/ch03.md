Chosen details where the chapter did not specify them:

- `read_file`: one-based inclusive ranges, omitted/zero start means 1, omitted/zero
  end means EOF; `max_bytes` omitted/zero means 32,768. A narrower requested range
  is selected before capping. A visible truncation marker suggests a narrower
  range or larger cap. The cap bounds model output, not filesystem memory; this
  small implementation reads the local file into memory first.
- `search_files`: Go regular expressions, recursive regular-file traversal,
  `context_lines` defaults to zero. Matching lines use `path:line:text`, context
  uses `path-line-text`; overlapping/adjacent windows merge and separated groups
  use `--`. Directory symlinks are not followed by `WalkDir`. No new search options
  or external grep dependency were added.
- `list_directory`: sorted immediate entries, `/` after directory names.
- `write_file`: creates parent directories; new-file creation uses `O_EXCL` so
  refusal is enforced at open. Existing replacement needs `overwrite:true`;
  `append:true` appends without that flag. Refusal reports the existing size.
- `edit_file`: exact, unique, nonempty anchor only. Zero, multiple and overlapping
  matches refuse without changing bytes; the result reports the observed count
  and asks for a fresh read and unique anchor. No fuzzy or rewrite fallback.
- `run_command`: fresh `/bin/sh -c` each call, launch-directory working state,
  labeled stdout/stderr/exit code. It blocks until completion. The coordinator
  reminded me that provider credentials must not enter unrelated subprocesses;
  the shell environment filters `LLM_API_KEY`, `ANTHROPIC_API_KEY`,
  `OPENAI_API_KEY`, and `GEMINI_API_KEY`, preserving ordinary build settings.
  This is a narrow credential-lifetime fix, not a confinement claim.
