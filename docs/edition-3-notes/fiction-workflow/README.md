# Fiction workflow: initial memory experiment

Prepared inputs, not installed Agent identities or an executed experiment.

Bill selected separate Author and Editor identities with initially empty
MEMORY.md files. The intended baseline allows each role to develop its own
memory during the book. Conversations continue through a chapter's revision
loop and start fresh for the next chapter; role memory is intended to survive
that boundary. Role-home preparation, native child context transfer and the complete book
driver have local tests using synthetic inputs and provider responses. This does not establish model learning or a live fiction result.
Keep these baseline files unchanged when a run starts; use run-owned copies.

Bill reports that giving CodeRhapsody's memory to a writing Agent improved even
the first chapter. That motivates a later comparison with copies of Cadence's
then-current memory. It is not a measured result of this workflow. No Cadence
memory has been copied here. Preparing that comparison, selecting safe relevant
material and running either experiment are separate work, not completed effects.

Detail and global reviewers are intended to start fresh for each review; these
files seed only the Author and Editor. Memory is not manuscript authority or a
tool grant. Local role-transfer and restart checks do not establish a successful live
fiction run or literary quality.
