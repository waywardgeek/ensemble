## Integration-boundary structure plan (new-contract review requested)

- Ensemble owns Agents, display subscriptions, completion collections, logger and application job handles. Collections have a common Ensemble back-pointer and their own drain lock. Each immutable request handle owns its completion/done notification; collections do not consume that handle.
- Agent owns config, history/reducer, Engine, Registry, Jobs and one Actor. The private actor/engine adapters expose the same Agent, not a sibling capability bag. Agent's short history mutex protects public snapshots; actor alone invokes runtime durable validate/persist/apply. Offline replay invokes that reducer without starting an actor.
- Actor lives in llm and stores its common ActorAgent parent. Shared mailbox/event/completion/report declarations are in common. Mailbox mutex guards growable admission queue and stopped flag only. Active request, pending FIFO, operation generation, cancellation and state belong to its sole drainer. Configuration is captured at turn activation; the pre-existing operation guard rejects live config changes until turn completion.
- Engine owns its HTTP client and model-attributed usage mutex. Workers receive body/config snapshots, use cancelable contexts, return tagged parsed facts, and cannot commit history. Actor assigns response sequence/call IDs on append and accounts accepted usage once.
- Jobs owns job state, spool, report cursor and process lifetime. Prepared reports carry owned snapshot plus cursor interval; only accepted reports commit the cursor. Job terminal facts post without waiting while holding Jobs' lock. Actor recognizes an attributable terminal fact included in an interrupt snapshot and deduplicates the queued fact; stale model/report operations are discarded.
- Close closes admission in mailbox order, settles queued/active requests, then a cleanup worker kills/drains managed jobs and joins cancelable model/report workers while actor continues accepting terminal facts. Only the final cleanup message closes the log/drainer. Nonkillable local work keeps prior truthful killed semantics.
- Display subscriptions have separate bounded queues; overflow closes that subscription with exposed reason, independent of reliable completion. Subscriber callbacks never run on actor. GUI remains an optional module using public owner APIs.

## Clarification raised during asynchronous client review

§5.7 says a real failed request closes the CLI and queued new-format requests receive stopped completions during cleanup; §5.1/§5.2 give all clients one automatically progressing Agent queue, and §5.7 allows a later library request after a nonfaulting provider error. At present the CLI closes immediately when it receives the reliable error completion, but the actor could activate the next admitted request before the client goroutine observes that completion. Question to author/coordinator: does “queued ... during cleanup” refer to requests still queued when close reaches the actor, or must a CLI opt into an explicit stop-on-provider-error admission policy to guarantee no next request begins? The former is implementable under mailbox ordering without adding client policy to Agent; the latter needs an explicit contract. No claim that all pre-existing queued prompts are stopped is made while this distinction is unresolved. Continuing independent evidence/test work.
