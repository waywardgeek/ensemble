## Primary browser contracts checked

These sources were consulted on October 8, 2026; they support mechanism choices,
not observed success of an implementation:

- [WHATWG WebSockets](https://websockets.spec.whatwg.org/) specifies the browser
  send/message/close interface and bufferedAmount. Application logical channels
  and their rights are our protocol, not a WebSocket feature inferred from a
  socket URL. Bounded multiplexing and endpoint-only close need explicit owners.
- [DOM event trust](https://dom.spec.whatwg.org/#dom-event-istrusted) distinguishes
  constructed/dispatched events from trusted user-agent events. A synthetic click
  or input is not a promise of user-activation privileges. The outline routes
  supported actions through the owned Page operation instead.
- [WAI-ARIA selected state](https://www.w3.org/TR/wai-aria-1.2/#aria-selected)
  describes state that a widget must make meaningful. Snapshot labels need
  actual selected/expanded/checked/disabled facts, not guessed CSS meaning.
- The [HTML input value surface](https://html.spec.whatwg.org/multipage/input.html#dom-input-value)
  was opened as a reference lead. A broad text search did not isolate the desired
  value-assignment/event passage; no additional normative claim is based on that
  search result. The historical input failure is independently visible in the
  selected local diffs above.

## Design boundary carried into the outline

The browser-bootstrap proposal keeps Chapter 11's freeze-before-Agent rule:
create an unbound view/endpoint, explicitly select it, discover, construct or
resume with matching bindings, then mount the Page into that same view. No tool
is registered lazily after construction. Browser reconnect has a new generation;
old click/input operations are never replayed onto a replacement tab.

Application-selected integration policy is transport-independent creation data.
Skill activation may enable a fixed policy and Agent lease; it cannot make a
peer's ephemeral annotation authoritative. Unload must distinguish automatic
sampling from previously admitted model Jobs and preserve other Agents' leases.
The outline proposes canceling automatic collection on unload while retaining
ordinary Job lifetime, subject to coordinator review.

The remaining capture decision is real: Chapter 2 ephemera consume at an actual
request_sent attempt, whereas automatically refreshed observations may be
abandoned before any request. Reusing that pending queue without an explicit
discard rule could replay stale screen data. The outline asks for an exact
recorded-sample/attempt boundary and format extension before teaching code.
It also asks for precise targeted retrieval, selector/remount identity and
human-owned draft protection. Those are observable behavior choices, not method
spelling for the coordinator to guess on the student's behalf.

All limits and timeouts proposed in the outline are design candidates. No
performance measurement, provider identity, cost, source-bound screenshot,
actual model response or completed acceptance result has been fabricated.

## Coordinator resolution after initial freeze

The initial outline/evidence is preserved at 54806a6. The coordinator then
accepted the concrete 120-second boot, selected-view scope and Agent lease model,
strict v3 for nonempty policy, mount-bound control identifiers, protected human
drafts and bounded versioned artifact reads. Omission counts may explicitly be
unknown when bounded traversal cannot establish exact totals. These are working
design decisions, not measured results or additional Bill rulings.

The separate sample-fact proposal was declined in favor of direct request_sent
capture. The collector owns transient candidates; Actor revalidates and stores
the complete samples in the request event before HTTP, together with existing
hint/ephemera consumption. A canceled pre-event collection leaves no durable
sample, while a failed HTTP request retains the data it attempted to send.
Unload/interrupt/close fence collection; a changed generation requires a fresh
whole collection. This avoids a second durable pending queue and its retirement
protocol.

The author checked this against Chapter 2 §§2.1/2.3/2.5, Chapter 5 request/hint
rules, Chapter 9 §9.7 ordering and Chapter 11 §11.8 offline reconstruction. No
published rule requires a separate observation event. Pure rendering must accept
owned sample input explicitly; reconstruction selects the captured request payload
and its preceding prefix. A bare prefix render cannot fetch or guess observations.
The full draft must teach that distinction and the exact new payload.

Core cannot establish read-only behavior from a GUI tool name. Trusted typed
creation policy selects fixed aliases and argument objects; the optional GUI
validates its own observational defaults. Other embedders choose responsible
operations. This replaces the initial outline's ambiguous suggestion that core
could validate a fixed GUI operation without importing GUI knowledge.
