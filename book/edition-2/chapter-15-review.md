## Recommended coherent boundary

Use the log as authority for applied memory; external files supply explicit
captured refresh inputs, and generated files are exports of already committed
state. Compression returns a candidate to the existing Actor. One durable fact
retires exact selected source versions and installs generated bytes together.
Neither export success nor the model's assertion of a good summary commits it.

Prefer a fresh v5 capability with default-disabled scheduling and preserved old
profile routes. Retain the exact Skills union and ordinary model-request budget.
Use an explicitly paid idle compression control, plus separately enabled
post-handoff scheduling within an active turn's remaining budget. This is the
coordinator's stated leaning, not a final published contract or new Bill ruling.

## D1–D8 findings and options

**D1 — Give each band one role and a finite destination.** Five bands are
reasonable vocabulary, but the graph must precede thresholds. The simplest
teachable split is operator-refreshed profile/curated input plus a finite chain
of generated session/recent/older memory, with the last generated band terminal.
Do not quietly make a curated file an automatic merge destination. An alternative
graph is possible if every edge, disabled destination and terminal overflow is
printed. State whether disabling affects scheduling, request visibility or both;
durable content visibility and current scheduling policy cannot be one fictitious
atomic checkbox. Retain hidden/disabled entries as evidence where promised, and
define their contribution to pressure separately. Generated text remains
attributed data even if phrased in first person. It cannot replace the primary,
enduring instructions, grants or connection policy.

**D2 — Make refresh an explicit input transaction.** Support the recommended
log authority and explicit refresh on resume, with no startup/offline scan.
Capture a bounded complete selected set before one all-or-nothing application.
Define stable logical source IDs separately from file paths and accepted content
versions. Specify additions, omissions/deletions, duplicate IDs, malformed files
and no-op content; otherwise “refresh a band” cannot be independently checked.
An unchanged refresh should not invent a version. Physical relocation can preserve
logical selection, as catalog relocation does, without treating a different
logical source as the same input merely because its text matches. Safe state
reports applied revision and refresh/export outcome without absolute private paths.

The reader's correction story becomes: edit the selected source, explicitly
refresh, observe its newly accepted bytes, and reconstruct the earlier request
unchanged. An automatic refresh alternative would need an explicitly selected
live operation after validation; ordinary resume alone currently promises no
unrequested work and historical reconstruction must remain zero-I/O.

**D3 — Separate durable replacement from derived file installation.** Commit
retirement plus generated text before export. Failed export leaves usable committed
memory with visible export failure, not rolled-back conversation or deleted source.
Avoid two mutable authorities by separating operator input files from generated
exports; reject accidental overlap. The simplest writer scope is one Agent-owned
export area under its locked store, with immutable memory-ID/version filenames
and bounded retained exports. Read-only inputs may be deliberately shared.
If exports live elsewhere, explicitly teach writer/path claims and checked
installation; an incidental shared directory is not a concurrency contract.
Do not retry export by repeating the paid generation. A requested re-export can
use committed bytes. No source deletion or unlimited corpus growth is implied.

**D4 — Bound one operation through shutdown and restart.** Keep the proposed
Actor-owned operation and child worker with actual owner/logger access. Engine
remains the transport/usage owner through Agent. Holding subsequent model
admission must not hold the control loop, pause/interrupt path, or checkpoint
writer locks. At most one operation exists, with explicit input/output/deadline
and total fold/request caps; a cascade cannot create an unbounded paid queue.

Define its durable attempt start, accepted-result settlement and terminal
disposition before code. A checkpoint with an unresolved operation is busy;
close cancels/joins it and records truthful cleanup when the writer is healthy.
Prefer Chapter 10's fail-closed unfinished resume, rather than inventing an
automatic abandoned-attempt repair. An append failure may prevent disposition;
it must retain the inherited terminal fault. An accepted response can contribute
usage while a stale or canceled replacement leaves source unchanged. The model's
response and the memory transition therefore need distinct identities/outcomes.

**D5 — Select represented source after the handoff, never secretly recover it.**
Chapter 14 has already removed tool pairs by the time its handoff commits. Source
must be surviving represented dialogue, working notes or applied memory versions.
Do not fetch old tool bodies from the full log, snapshot, artifact locator or
MCP endpoint to fill the compressor input; a snapshot-only session may lack them.
The coordinator independently identified and agrees with this intersection.

Publish exact segment boundaries and eligible part purposes. A sequence range
cannot safely select a manual, enduring instruction or unconsumed hint just
because it lies between dialogue entries. Preserve current work, the newest
handoff note and all required logical anchors. Explain which older ordinary
dialogue may now be retired under v5, extending Chapter 14's deliberately narrower
tool-only removal. A lossy summary is not proof that the original goal survived.

Prefer protecting an entire opaque-containing unit. Exact compatible extraction
would be a separate taught feature; silently stripping opaque material or
flattening a signed block into ordinary text is not an acceptable shortcut.
Define oldest *eligible* selection and honest protected overshoot, including
whether protected units can be skipped. Validate the post-replacement ordinary
projection under the inherited target rules; helper success does not establish
that a remote provider accepts the changed foreground prefix.

**D6 — Refuse pressure without changing execution authority.** Support visible
pressure refusal over a forced one-tool union. Chapter 9's exact active union
and mandatory management tools otherwise conflict with the old forcing design.
Pressure measures the current represented projection using one printed neutral
measure, not accumulated usage or a promised token-window size. Preserve whole
units, strict high/low comparisons and truthful saturation when protected/current
material alone is too large. No forced HTTP request, silent source loss or retry
loop solves that condition.

The reader needs a non-model recovery route when the next ordinary request is
blocked: an explicit idle handoff can establish a boundary, then the separately
paid compression control can attempt a permitted fold. If nothing is eligible,
say so; do not ask the blocked model to produce the only allowed recovery tool.
Define whether the prompt remains pending, is refused before turn start, or ends
with a safe outcome. That choice determines whether it must be resubmitted and
must not silently consume the user's text.

**D7 — Extend formats and ceilings explicitly.** Prefer an explicit fresh v5
memory profile with exact initializer/anchor/identity/checkpoint agreement.
Preserve strict v1–v4 decoders and deliberately available compatible ceilings and
catalogs. Capability, logical file selection and scope belong to creation
identity; current captured text and enabled scheduling do not become competing
identity/policy authorities. Define how a memory profile implies or selects the
Chapter 14 context capability, including the valid memory-enabled/context-disabled
case. Do not let two profile flags silently pick different versions.

Extend the existing Agent policy through a strict new version with explicit
older-version defaults, no-write reads/no-ops and pre-write profile validation.
Keep old routes usable without silently adding a memory handler or replacing
their catalog. Print exact raw/encoded bounds, full uint64 identity/version
domains and whole-group allocation exhaustion before fields appear in browser
keys. Snapshot-only reconstruction retains Chapter 10/14's represented-history
limits; source retirement does not justify a hidden duplicate archive.

**D8 — Make helper cost a visible request purpose.** A single submit schema is
an output contract, not a Registry grant. Use the existing Engine adapters with
captured bounded source and a literal helper prompt/response shape for all three
providers. No tools, Skills changes, observations or GUI access run inside that
worker. Arbitrary source instructions remain data; returned calls never dispatch.
Malformed/multiple/unknown submissions, excessive output and inadequate reduction
settle failure without retiring source or automatically retrying.

The outline's “after a handoff” trigger intersects Chapter 14's explicit promise
that public `/handoff` and browser controls make no model request. Preserve that
promise with a separate visibly paid `/compress`/public equivalent for idle work;
if the final design instead schedules from an idle handoff, print that new opt-in
behavior and its completion/cost boundary explicitly. A handoff acknowledgement
still reports only its own committed note/cut.

For turn-owned helpers, consume the active turn's remaining captured
max_model_requests in addition to a bounded helper/trigger allowance, never a
fresh allowance that bypasses the turn cap. At its last request, a successfully
committed handoff stays committed even when no helper budget remains. Idle paid
operations need their own captured, visible finite allowance and operation
completion, since no turn exists to charge. Count starts before transport and
do not reset the budget between cascade folds, failure or cancellation.

Record exact helper inputs, producing provenance, response/candidate disposition
and valid normalized usage once, even when replacement is rejected later. A
transport failure or missing usage cannot supply invented zero usage or a valid
accepted settlement; keep its refusal/unknown-usage distinction. Foreground
usage totals and UI displays must explain helper purpose without relabeling a
compression response as a user answer or auto-speaking it. Replay makes no call
and cannot count the same accepted response twice.

## Full-draft and evidence requirements

The outline's required live coverage is appropriate preparation: real handoff,
compression and graduation, file correction, disabled behavior, restart, public
two-Agent isolation and actual browser controls on all three providers. A final
concrete matrix must count ordinary and helper requests together before launch.
Evaluate fact survival from the resulting request without leaking removed source
or alternate answer-bearing prompts into the evaluator. A valid submit object
and smaller bytes alone establish neither factual retention nor task quality.

Keep deterministic controls for atomic append/export boundaries, exact/+1 sizes,
stale completion, disabled neighbors, terminal saturation and shutdown. An
oldest-first fixture needs a surviving newer unit, and zero-call replay must cover
startup as well as reconstruction. No historical fake compressor becomes a
new live result. The historical incident remains a promising human stake, with
its independent verification deferred to full manuscript review.
