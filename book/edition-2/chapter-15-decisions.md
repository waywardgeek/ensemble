## Applied memory, inputs and exports

Accept D1–D3 with five typed bands: operator-refreshed profile notes and curated
memory, plus generated session, recent and older memory. The generated chain is
finite, ending at older memory. Profile/curated inputs are not automatic merge
destinations. Choose and teach exact thresholds, selection grain and terminal
saturation; no label promises an achieved compression ratio.

The accepted event history governs applied memory. External files are explicitly
captured inputs, never silently rescanned on resume or historical replay. Refresh
validates a bounded complete selected set, then commits all additions, changes
and removals together. Define logical IDs, absent entries, duplicates and unchanged
content precisely; unchanged refresh does not invent a revision. Physical paths
and logical scope are separate, and safe browser state exposes no private paths.

Separate durable content visibility from current compression scheduling policy.
A content enable/disable operation cannot pretend to be atomic with a separate
policy-file write. Hidden entries retain their promised evidence and versions;
the chapter must say how each state contributes to request rendering and pressure.
Profile notes remain ordinary attributed data, never a new System, primary,
grant, integration configuration or credential authority.

One memory replacement fact retires exact selected source versions and installs
the generated text atomically. Only afterward may derived export occur. Use an
Agent-owned export area under its locked session store, with immutable ID/version
filenames and finite retention bounds. Operator inputs may be shared read-only;
they must not overlap generated destinations. Export failure leaves the committed
memory usable and visibly unsaved. Re-export uses committed bytes without paying
for generation again. Neither folding nor export deletes source files.

## Source, ownership and lifetime

Accept D4–D5: one Actor-owned bounded operation and its worker, reaching Engine
through the actual parent chain. Engine owns provider transport and per-producing-
model usage. Actor orders durable admission through Agent; EventLog owns the sole
append descriptor. SessionStore owns its lock and checkpoint work, not a second
append writer. Memory's file service owns scan/export resources, not another
mutable conversation.

Compression selects only presently represented complete units: surviving
dialogue, working notes or applied memory versions. Chapter 14's removed tool
bodies are not secretly fetched from old logs, artifacts, snapshots or MCP.
Publish exact segment boundaries and eligible purposes. Preserve current work,
the newest handoff note, manuals, enduring instructions and pending hint anchors.
The new v5 contract must explicitly authorize any retirement of older ordinary
dialogue; Chapter 14 only removed tool pairs.

Protect an entire opaque-containing unit in this edition. Do not flatten signed
material or strip opaque parts to obtain a summary. Select the oldest eligible
units, allowing protected units to be skipped while retaining their order and
counting their contribution to honest pressure. Validate the resulting ordinary
projection under inherited target compatibility; a valid helper response proves
neither remote acceptance nor semantic preservation.

Define durable operation start, accepted response settlement and terminal
disposition. An unresolved helper makes checkpoint busy. Controls remain
responsive while further model admission waits. Close cancels, joins and records
truthful cleanup while the writer is healthy; failed appends retain terminal
failure. A crash with an unfinished attempt remains fail-closed under Chapter 10.
No automatic abandonment or replay-time repair is introduced. Stale/canceled
replacement may still have genuinely accepted usage, accounted once.

## Explicit pressure and spending

Accept D6: pressure uses the current represented projection and a printed neutral
byte measure. Do not change Skills' exact grant union or force a handoff-only tool
set. Preserve complete units, strict threshold rules and visible saturation when
protected/current material prevents reduction. No automatic retry loop hides it.

At a blocked ordinary send boundary, finish the turn with a stable memory-pressure
outcome and retain already accepted prompt/history bytes. Make no HTTP request
at that boundary. The CLI/browser must explain that the prompt was retained,
whether earlier requests in that turn occurred, and that no automatic resend is
pending. After idle recovery the user can send a follow-up such as “continue”;
they must not unknowingly duplicate their original prompt. Normal request-budget
exhaustion still prevents the next request; pressure grants no extra allowance.

Preserve the zero-model promise of public `/handoff` and browser context_handoff.
Introduce a separate visibly paid idle compression control with a captured finite
operation allowance and explicit completion. Automatic compression after a
model-tool handoff is a separately enabled v5 scheduling feature, disabled by
default. A handoff acknowledgement reports its own committed note/cut, never the
later compressor result. A committed handoff stays committed when helper budget
is exhausted; report the skipped/deferred compression honestly.

Accept D8: every turn-owned helper attempt consumes the active turn's remaining
captured max_model_requests as well as its bounded per-trigger allowance. Idle
paid compression has a separately displayed finite operation allowance because
there is no active turn. Count starts before transport and never reset an
allowance between cascade folds, failures or cancellation. One bounded attempt
per fold; no automatic retries. Exact input/output bounds and deadlines belong
in the full contract and the later reviewed live plan.

The helper's single submit schema is an output format, not an installed execution
tool. It receives only captured source and the taught prompt; no tools, callbacks,
Skills changes or live GUI observations execute inside it. Record exact request
inputs, response provenance, valid usage and distinct candidate disposition.
Malformed output, missing usage, transport failure and insufficient reduction
remain distinguishable; none silently retires source or invents zero cost.
Helper output is not a user-facing assistant answer and must not auto-speak.
