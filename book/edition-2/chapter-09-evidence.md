## Inherited grader scope, read rather than run

The old evaluator has nine checks totaling 100 points: initial tools, primary
system body, full-primary tools, dynamic load, progressive disclosure,
dependency contribution, variable substitution, blocked load and old Chapter 9
parity. Its own fixture driver uses the Messages API with `fake-model`; this
does not establish the new three-provider skills paths.

Concrete limits in those checks:

- Initial/full-primary checks require certain names, with only edit/write
  excluded from the initial set. They do not establish an exact effective
  grant set or reject all unintended handlers.
- The primary check looks for expected text in the first request. It does not
  prove primary-byte stability across loads, precedence with public System
  configuration, frozen file bytes or replay independence from the catalog.
- Dynamic load checks that edit/write appear and the count increases.
  Disclosure checks that search becomes callable through a scripted load;
  dependency handling is inferred from `list_directory` appearing. Missing
  dependencies, cycles, diamonds, duplicate loads and atomic rollback are absent.
- No unload path is driven. There is no shared-contributor test, revocation
  check, ongoing-job distinction or actual attempted disabled-tool dispatch.
- Blocked load passes on words such as “error,” “cannot” or “not found” in a
  result. A structured refusal, no state change and no side effect need their
  own controls; a reassuring string is insufficient.
- The improved variable check inspects the next whole request and absence from
  the earlier one. It does not cover candidate-state lists, literal dollars,
  unknown tokens, recursive expansion, per-Agent custom values or secrets.
- The driver expects one combined old binary, `--gui-dir`, uncorrelated socket
  commands without the new Origin and ID requirements, and a raw `turn_ended`
  message. Its old parity chain cannot replace the new optional-module, watch,
  browser settings, policy and public-consumer checks.

Keep the inherited diagnostic and its passing legacy controls. New contract-

## Outline proposals requiring review before drafting

The outline chooses an Agent-owned Skills service with actor-ordered transitions,
an immutable catalog loaded before Agent publication, installed handlers as a
capability ceiling, distinct explicit roots/dependency contributors, dedicated
recorded instruction material, and safe watch/CLI/browser projections. These are
proposals for review. They are not additional user rulings or hidden grader
requirements.

Primary/System precedence and custom-variable scope remain the two explicit
policy questions. A primary should not silently overwrite a caller's requested
System setting or be silently replaced through a later update. An application
needs a public variable extension without a closure bag. The outline recommends
immutable scalar custom bindings with computed built-in lists; requiring arbitrary
computed callbacks would need a separately specified owner and execution boundary.

The full draft also needs exact file/resource limits, variable grammar, transition
and no-op payloads, provider render fixtures, management-tool one-shot-limit
behavior and a visible skill-state contract. Finalize those before checker or
student work. No sentence about immutable primary text is a measured provider
cache claim; changing declarations may still change request prefixes.
