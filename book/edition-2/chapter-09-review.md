Coordinator review, October 8, 2026, of outline/research checkpoint `db86e0c`.

The design brings later lessons to the first introduction: active manuals get
dedicated recorded material rather than living only inside clearable tool
results; effective tool grants govern admission as well as declarations; and
unsupported integration configuration fails explicitly. Dependencies, discovery
and explicit load roots have different meanings. Unload revokes capabilities
without pretending to erase prior instructions or cancel already admitted jobs.

The coordinator settles the two outline choices for drafting:

- In skill mode, reject a nonempty competing creation-time `Config.System`.
  The rendered primary supplies the base instruction. No-skills mode preserves
  earlier behavior. Existing explicit enduring instruction appends remain
  allowed as supplements under the inherited recording/rendering rules; they
  do not replace the primary identity or its rendered bytes. The total provider
  prefix can change after such an append, so no cache-hit promise follows.
  Teach CLI default/conflict handling explicitly rather than silently overwriting
  the caller's configuration.
- Custom variables are immutable scalar per-Agent bindings at this stage.
  Agent owns authoritative creation configuration, including bindings and primary
  selection. Skills reaches it through its Agent parent and owns the parsed
  catalog, active closure, material state and derived renderings. Built-in
  TOOLS/SKILLS lists are computed over the complete candidate. Teach one-pass
  expansion, literal dollar syntax, unknown-variable refusal and no environment
  fallback; computed custom callbacks are not required in this chapter.

These are working design choices within the settled architecture, not new Bill
rulings. They preserve the method's public extension point without introducing
sibling-service closures or relocating Agent configuration onto a convenient
child. Public name spelling remains the student's decision.

The proposed single-commit formulation is accepted for drafting: Skills prepares
an owned candidate; Actor serializes a durable initialization/change fact whose
successful append determines the committed state before publication and result.
A later result-append failure follows the inherited terminal failure semantics;
it cannot claim the durable capability change rolled back. Actor-bound queries
and snapshots must observe coherent committed state. New dynamic/dependency
manuals enter chronological context at the completed batch boundary so tool
call/result pairs remain intact. Primary bytes must not be duplicated into that
material stream or changed by an ordinary dynamic load.
