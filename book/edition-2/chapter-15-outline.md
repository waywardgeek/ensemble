# Chapter 15 outline: Remember the work, retain the evidence

Through-line stake: a reader wants an Agent to continue a long task and accept
corrections to its saved knowledge without treating a lossy summary as either
the original evidence or a new source of authority.

The old opener also attributes a sharp improvement to restored memory after a

intelligence gain and internal-paper readership. No raw experiment receipt has

Proposed sequence:

1. Distinguish a retained original, a working note and a generated memory. A
   summary can omit or misstate facts. Mechanically removing duplicate source
   text does not prove that its meaning was preserved.
2. Extend Chapter 14's handoff boundary into a compression opportunity. Preserve
   its atomic note/cut and paired-result rules; do not turn a staged result into
   a claim that a later compressor has completed.
3. Give the creator ownership of the compression operation and exact selected
   source. A one-shot compressor produces a candidate, never mutates the Agent.
4. Commit replacement and generated bytes together. Explain failed model calls,
   interrupted work and append failures before discussing automatic cascades.
5. Introduce typed memory bands and canonical placement while preserving event
   provenance. No Seq:0 trick is needed to separate ordering from identity.
6. Make user-edited files explicit captured inputs, with bounded refresh and
   truthful distinction between current applied memory and its external source.
7. Select oldest whole units by current size; account for indivisible units,
   disabled destinations, terminal-band saturation and bounded paid work.
8. Carry memory through exact replay, snapshots, restart and public multi-Agent
   use, keeping Skills, policy, integration and credential boundaries intact.
9. Demonstrate retained facts and actual failures through CLI/browser/public
   consumers, measuring generated quality separately from size and usage.

## Scope worth retaining and scope to resist

Retain bounded model-assisted compression of complete finished segments, recorded
output bytes, oldest-first graduation, independent enable/disable behavior,
captured external-memory refresh and deterministic zero-call historical replay.
The five historical bands are useful vocabulary, subject to D1 below: profile
notes (historical SOUL), curated memory, older compressed, recent compressed and
session memory. Labels 8x/64x should describe historical target tiers only if kept;
they cannot claim an achieved compression ratio.

Memory remains attributed data. Profile notes do not replace the Chapter 9 primary
or Chapter 10 creation System, and a memory cannot add tools, enable a skill,
configure a connection, move a policy file or supply credentials. The compressor
gets only its bounded captured source, not the Agent's execution rights or active
GUI observations. There is no autonomous second Agent, callback dependency bag,
tool-execution loop or historical-answer copy.

Avoid a new general background scheduler, cross-process shared writable corpus,
implicit migration, automatic provider fallback, guaranteed losslessness, signed
thinking extraction or whole-context-capacity promise. The old chapter's fixed
string compressor proves structural replacement, not semantic retention. The new
chapter needs both mechanical controls and honest actual generation results.

MCP parsing remains transport-independent. Any browser memory controls use the
optional GUI and public interfaces; the actual MCP-over-WebSocket endpoint is not
replaced by a core GUI dependency or used to grant the compressor default access.

## Proposed owner and data plan

| Work or state | Proposed owner / actual parent |
|---|---|
| Creation selection and current memory policy | Agent, through the existing policy service; a new profile is explicit |
| Applied entries, exact source selection and operation disposition | Existing Actor/reducer authority, using common serializable values |
| Memory file scanning/export | Agent-owned Memory service, reaching Agent and SessionStore through actual parent interfaces |
| One live compression operation | Actor-owned operation; captures source, purpose, policy/config generation and cancellation scope |
| Bounded compressor parser/request worker | Child of that operation, through common parent interfaces and logger access |
| Provider HTTP and normalized per-model usage | Existing Engine reached through Agent; request-local credentials stay there |
| Durable memory transition and usage settlement | Actor→Agent durable admission; EventLog owns the sole append descriptor; SessionStore owns lock/checkpoint work |
| GUI drafts/state/commands | Optional GUI public consumer; no authoritative memory slice or policy copy |

The Memory service must not become another conversation authority. It may own
external file identities, bounded scan candidates and export work, while the
reducer owns what the current request contains. Do not inject Engine, Skills and
Store as siblings into a compressor merely because it needs their facilities.

Each memory needs a stable ID distinct from event sequence and a typed purpose,
band, source identities, captured text/hash, producing provenance and applied
revision. Keep the event sequence that accepted it. Canonical rendering order is
a separate field/rule; it cannot erase provenance. A source selection references
whole finished segment identities and immutable memory versions, not only an
inclusive sequence range that might also contain a skill transition or hint.

At most one compression operation per Agent is proposed, with bounded input,
output, deadline and total calls per trigger. It returns an owned result to the
Actor. Controls remain responsive. Before commit, recheck source versions,
enabled state, cancellation and captured selection; a stale completion can retain
its accepted usage without replacing changed material. No worker applies state,
reads current GUI data or retries autonomously.

For D2, the revised user story is deliberate: edit the selected memory file,
refresh, observe a new captured version, then reconstruct the earlier request
unchanged. A file-path-only identity cannot tell whether content changed; a
content-only identity cannot say which logical memory was corrected. Both matter.
Raw private paths should not leak into browser-safe state.

For D3, retain original files by default. Cascading applied entries is not license
to delete a corpus or its older versions. Bound retained exports and fail visibly
at the documented limit; do not promise unlimited growth. File installation must
use exclusive/atomic checked writes with collision and symlink rules taught
before implementation, consistent with Chapters 4/10. Physical location may change
under an explicit compatible caller selection without rewriting historical bytes.

For D4/D8, an HTTP response can spend tokens even if its summary is invalid or
superseded. Usage belongs to the producing model and needs a once-only durable
attempt settlement distinct from whether the replacement was accepted. There
must be no double count on replay or no-cost claim after missing usage.

## Exact behavior to settle in the contract

Publish the single replacement payload before checker work: exact selected
source IDs/versions, destination band and new memory ID, accepted generated text,
hash, source provenance, operation identity and reason. A public append must
match the current typed candidate; a valid-looking replacement snapshot cannot
retire unselected dialogue or fabricate a compressor result.

Specify what counts toward each band, byte bounds, high/low comparisons, selection
grain and terminal overshoot. Prefer oldest whole units until the source reaches
its low target, keeping the newest unit protected where promised. A single
oversized unit needs a truthful refusal/overshoot rule, not an infinite cascade.
An output larger than its configured cap or failing to reduce enough should
retain source and settle failure; do not keep retrying until the model cooperates.
Disabled destinations must refuse before spending or retiring source.

Define each enabled state as durable applied content selection, distinct from
mutable scheduling policy. A two-file policy write plus content append cannot
claim one atomic acknowledgement. Prefer explicit typed content controls over
a checkbox that quietly coordinates unrelated transactions. A whole refresh
must capture/validate bounded files before committing an all-or-nothing set;
partial scan failure cannot leave the reader with half of a corrected band.

The compressor prompt and single submit response must be literal enough to test
all three adapters. First-person attributed memory can preserve the historical
voice choice, but should say which source facts it summarizes. No request for
private chain-of-thought or asserted access to hidden reasoning. Unknown tools,
multiple submissions, malformed JSON, empty/oversized output, missing usage,
provider failure and interruption need separate outcomes. The worker's submit
is an output format, not a Registry grant or execution capability.

Define the placement of memory relative to base, surviving dialogue, skills,
working notes and captured observations. Existing primary bytes stay exact.
Canonical band order cannot reorder Chapter 9 H/S/P anchors within surviving
dialogue. Compacted source facts remain in the full log; snapshot-only imports
continue to expose represented history limits honestly. No recall mechanism is
added here; the following chapter can consume stable attributed memory entries.

## Required public, human and live evidence

Teach public owned state, idle/busy controls, typed refresh/enable/disable and
operation completion before browser wire commands. Show the current applied
memory version, source status, compression activity, safe failure and actual
usage. A human should be able to correct data without guessing whether a silent
rescan occurred. GUI close/late callback and same-DOM remount retain earlier
ownership rules; diagnostic summaries do not auto-speak as new assistant answers.

The planned all-provider live matrix includes actual CLI handoff→compression,
at least one graduation, changed-file capture, disable/enable, settled restart,
exact no-I/O replay, public two-Agent isolation and actual browser controls.
Use bounded fixtures with planted task facts and inspect what the next request
really contains. Separate fact-survival evaluation from successful JSON parsing:
the original source and alternate prompts must not leak the answer into the
evaluation request after the claimed replacement.

Deterministic tests cover exact/+1 sizes, stale completion, all append boundaries,
helper cancellation, disabled neighbor, single oversized unit, refused pressure,
old-profile compatibility, file collisions/scan failure and forged transitions.
Count compressor traffic directly from before launch through shutdown; counting
only ordinary turn requests is insufficient. An oldest-first control must leave
at least one newer unit behind so oldest/newest mutations are distinguishable.

Preserve historical grader results and gaps as research. A new independent
checker must use the printed contract/public behavior and meaningful mutations;
it must not force the student back into two-event deletion, cumulative pressure,
silent file reload or a combined GUI architecture. No complete Chapter 15 draft
or student handoff precedes the D1–D8 decision review.
