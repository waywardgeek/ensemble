# Chapter 5 independent contract review

Read on October 7, 2026: full new Chapter 5; complete current voice guide,
chapter-writing procedure, coding skill and architecture; full current Chapter 4.
The durable global review map supplies previously recorded forward lessons;
this review does not claim a fresh simultaneous reread of the entire old book.

The draft is ready for a student handoff after coordinator acceptance of its
working ownership choices and completion of predecessor gates. No implementation,
grader result, live demonstration or final validation is claimed.

The opener makes the limitation concrete: a retained background job does not
make a synchronous conversation responsive. The chapter then separates prompt
admission, explicit guidance, reliable request completion, transient display,
and shutdown. It carries forward parent ownership and logger reachability,
actual append-sequence call IDs, durable late job facts, truthful nonkillable
work, and the existing request bound. Barrier-based collection and responsiveness
checks avoid grading incidental scheduler timing. The fresh student does not
need to reproduce the historical special-purpose sleep tool.

Findings resolved in the published contract:

- The transient state vocabulary now includes `stopping`, matching its stated
  interruption/close transition.
- The new machine directives have published acceptance, hint/interrupt
  acknowledgement, completion and error shapes. Legacy successful prompt output
  remains separate; no grader needs to invent protocol fields.
- Preparing a worker report reserves its interval; only acceptance commits
  cursor consumption. Discarding a superseded report cannot lose unseen bytes.
  Equivalent Jobs-owned transactions remain permitted.
- Intentional interruption/cancellation keeps both CLI modes alive. Only
  genuine `error`/`round_limit` outcomes trigger the specified fatal request path.
  This preserves queued and later prompts during the intended control exercise.

The author's accompanying clarifications also require a real accepted final
call-free response before successful turn end, prohibit reused request IDs,
expose unsent hint counts, and give Ensemble ownership of completion collection.
These make the claimed behavior independently observable without requiring a
particular private method name or channel arrangement.

Implementation review must still examine cancellation/report races, cursor
transactions, actor/worker lock ordering, subscription overflow isolation,
stable request completions and shutdown faults. A contract review cannot prove
those properties. Actual human terminal demonstrations, the public workflow,
independent mutations and post-run first-edition comparison remain required.
