# Chapter 10 physical record controls

October 8, 2026. Coordinator preparation against the printed Chapter 10
read-boundary contract and inherited Chapter 9 framing. This is an additional
subset, not implementation acceptance or the complete storage-limit gate.

Run the checker without reading its implementation:

```sh
python3 scripts/edition2/accept_ch10_record_bounds.py CLI_BINARY --source-directory solutions/edition-2/main --receipt RECEIPT.json
```

The command creates an empty genuine session with the actual CLI. It inspects
that store before deriving fixtures from its accepted initializer. No prompt or
provider request is submitted. Each physical-size variant changes only JSON
whitespace, preserving a small positive parent and the same public projection.
It exercises both generic offline render and explicit offline session inspection.

Coverage prepared:

- Exact 64 MiB and one-over session initializer and ordinary records, separately
  with LF and with a complete final record at EOF.
- Inherited standalone ordinary limits, including the historical unterminated
  Scanner boundary, and unchanged header limits in a session.
- Invalid and interior initializers at small and expanded sizes; they cannot
  authorize a switch to session admission.
- Unchanged original file hashes, safe refusals, executable/checker hashes and
  a before/after production source map. A changed source/checker fails the run.

Temporary records are written incrementally, one file at a time. Hashing uses
bounded chunks; each case removes only its own log. This keeps temporary disk
use modest. It does **not** establish bounded allocations inside the executable.
No source-level read barrier or memory instrument is present. Write admission,
skill-envelope boundaries, total file/count/canonical-state limits, nesting and
runtime lifecycle remain other required checks. The observed source map is not
an attestation that the supplied executable was built from that map.

The ten fixture-writer/classifier oracle controls pass, retained in
checkpoint-evidence/ch10-record-bounds-oracle.json. They include rejecting an
unrelated command failure rather than crediting it as a storage refusal.
Runtime controls are unrun at preparation. `--small-only` offers an initial
fixture/public-path check, but passing it does not cover any large boundary.
The coordinator read the current CLI/offline reader and the earlier independent
Chapter 9 bound fixture while preparing these controls. The runner uses public
commands and printed/inherited behavior, without private field assumptions.
No student source was edited; no first-edition code, credentials or live-provider
