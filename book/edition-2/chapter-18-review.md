## Current documented surface

[reasoning guide](https://developers.openai.com/api/docs/guides/reasoning)
supports explicit summary opt-in, model-dependent modes and summary text within
a reasoning item's summary array. Off/auto is a reasonable narrow selection;
auto does not promise a particular length or a summary on every response.

The [streaming reference](https://developers.openai.com/api/reference/resources/responses/streaming-events)
defines summary part added/done and text delta/done events with item, output and
summary indexes. Part-done can report incomplete. These are separate completion
levels, so receiving a summary-done event cannot authorize tools or accepted usage.
The chapter should consume the documented summary surface only; other reasoning
content and encrypted payloads confer no new display permission.

The [plan inference guide](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)
requires account-specific model selection and streamed, nonstored Responses.
The [preview restrictions](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)
do not forbid reasoning.summary. This absence is compatible with the proposal,
not proof of a selected account/model's summary access. Preserve the distinction
between local unsupported selection, provider refusal, valid empty-summary output
and observed nonempty delivery. None permits automatic retry or funding fallback.

### S3. Specify assembly, settlement and cancellation once

including data supplied only by a done/terminal snapshot. A repeated snapshot
does not append the same words again. Finalization retains the original identities

Use literal positives and one-fact negatives for repeated indexes, ID rebinding,
